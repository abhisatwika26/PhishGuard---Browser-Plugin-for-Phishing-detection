# PhishGuard  
Hybrid Phishing Detection System for Gmail

## Overview

PhishGuard is a Chrome extension designed to detect phishing emails within Gmail using a hybrid detection approach. The system combines rule-based heuristic analysis with Large Language Model (LLM)-based semantic evaluation to provide accurate and explainable phishing risk classification.

This project was developed as a B.Tech Capstone Project under the School of Computer Science and Artificial Intelligence, SR University.

---

## Problem Statement

Phishing attacks continue to bypass traditional email filtering systems by using domain spoofing, link obfuscation, and context-aware language generated by AI tools. Most existing detection systems rely on static rules or server-side filtering, lack contextual understanding, and provide minimal explanation to users.

PhishGuard addresses this problem by integrating metadata-based rule checks with contextual semantic reasoning directly inside the Gmail interface while maintaining user privacy.

---

## Key Features

### Rule-Based Heuristic Analysis

- Sender display name and domain mismatch detection  
- Reply-To address inconsistency detection  
- SPF, DKIM, and DMARC authentication validation  
- Suspicious keyword detection  
- Hyperlink anchor text and URL mismatch detection  
- Weighted phishing risk scoring  

### LLM-Based Semantic Evaluation

- Triggered only for medium-risk emails  
- Analyzes tone, urgency, and intent  
- Detects impersonation and social engineering patterns  
- Returns structured risk classification with explanation  

### Risk Classification

Emails are classified into:

- Low Risk  
- Medium Risk  
- High Risk  

Each result includes:

- Risk score  
- Clear explanation  
- Identified warning indicators  

---

## System Architecture

The system consists of four main components:

### 1. Chrome Extension

- Detects when a Gmail message is opened  
- Extracts message ID  
- Displays risk classification in a side panel  

### 2. Flask Backend

- Handles Gmail API integration  
- Authenticates using OAuth  
- Retrieves email headers and content  
- Performs rule-based scoring  

### 3. Node.js Proxy Server

- Interfaces between backend and LLM  
- Prepares structured prompts  
- Validates and forwards responses  

### 4. Ollama LLM

- Performs contextual semantic analysis  
- Generates risk level, score, and explanation  

---

## Workflow

1. User opens an email in Gmail  
2. Chrome extension detects the email  
3. Metadata and content are extracted  
4. Rule-based scoring is performed  
5. If the email is clearly safe or malicious, the result is displayed immediately  
6. If the email falls into a medium-risk range, it is forwarded for LLM-based semantic evaluation  
7. Final risk classification and explanation are shown in the extension panel

---

## Security and Privacy

- Email data is not permanently stored  
- Minimal text is sent for LLM evaluation  
- All external communication uses secure protocols  
- Rule-based analysis is performed locally when possible  

---

## Testing and Evaluation

The system was tested using:

- Legitimate service notification emails  
- Phishing emails impersonating trusted brands  
- Ambiguous emails with mixed indicators  

The hybrid approach improved detection accuracy while reducing false positives compared to rule-based methods alone.

---

## Limitations

- Designed primarily for Gmail  
- Depends on Gmail DOM structure stability  
- LLM evaluation may introduce minor latency  
- The system performs detection only and does not block emails  
- No long-term learning or historical storage is implemented
